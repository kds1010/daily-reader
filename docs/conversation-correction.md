# 文字起こしの文脈補正

文字起こし後に、文脈から補正案を作る工程と、その案が元の意味を変えていないかを
点検する工程を分けます。読みやすさだけを理由に、発言内容や予定を補いません。
音声認識の原文、発話ID、話者、音声内の時刻は保持し、補正は別の版として保存します。
発話時刻に結び付いたGPSも引き継ぎます。

## 処理の流れ

1. Mac内で音声を文字起こしし、原文と認識診断を保存します。
2. 前後の発言と、関連する参照情報から、句読点・表記ゆれ・誤認識の補正案を作ります。
3. 別のモデル呼び出しで、原文・前後の発言・補正案を比較します。数字、日時、否定、
   名前、未完了の約束など、意味が変わる修正は慎重に扱います。
4. 採用できる補正だけを要約とタスク抽出へ渡します。判断できない箇所は原文を保ち、
   確認が必要なことを表示します。

例えば「来週の予定はまだ決まっていません」を「来週に予定があります」へ直したり、
「前の会議は10時だった」という情報で今回の開始時刻を10時にしたりしてはいけません。
前後に同じ製品名が明確に出ている場合の表記統一とは区別します。

## 原文と根拠

会話詳細から、原文、補正案、採用された本文、理由、検証結果、参照情報を確認できます。
未採用の案は補正済み本文として表示しません。要約・抽出項目の引用には元の発言を残し、
補正文と補正版を別に持たせます。確認済み候補、追加済みの用事、以前の判断根拠を
補正処理だけで書き換えません。

## 過去の会話を使う意味

過去の情報は用語や話題を理解する手掛かりです。以前の希望を現在の依頼へ変えたり、
過去の予定を新しい予定として抽出したりしません。参照した情報は出典とともに保存し、
今回の発言とは分けて扱います。同じ「話者1」という番号だけでは同じ人と判定しません。

対象録音と過去録音の話者が、既存の人物対応で「自分」と確認されている場合に使用します。
過去録音の日時が確認済みで、対象録音より前であることも必要です。保存・承認した項目の
根拠から、今回に関連する短い原文を選びます。日時不明の録音、未確認の人物対応、
無関係な話題から不足分を埋めません。条件に合う過去情報がない場合も、今回の録音内の
文脈補正は利用できます。

過去の会話を使うためだけに、本人のプロフィールや話者を自動推定しません。
補正画面には実際に使った参照情報を表示し、参照情報がない場合はその理由を表示します。

## 品質の限界

意味の点検は、原音との一致を保証するものではありません。文法が自然でも認識が
間違っている可能性は残ります。聞き取れなかった内容や、文字起こしに抜けた区間は、
文章だけから復元できません。認識対象が短いなどの既存診断も引き続き確認してください。

原音はMac外へ送りません。補正・意味の点検は、既存のChatGPTログイン済みCodex CLIを
一時セッション・読み取り専用・構造化出力で使用します。GPS・健康・カレンダーを
補正のために外部送信する範囲は増やしません。

実録音の正解文がない場合、補正件数を認識精度の改善率と扱いません。原文が維持されること、
誤補正が保留されること、根拠と時刻が追跡できることと、内容の正確さを区別して検証します。
