# 会話ごとの振り返り

会話タブの中心を、取り込みフォームと全録音の候補一覧から、録音ごとの振り返りへ変更します。
録音日時、話した内容、抽出された項目、GPSの照合状況を同じカードで確認し、詳細で根拠を読みます。
録音の追加は「取り込む」から開きます。原音・原文と既存の採用履歴は保持します。

## 一覧と詳細で分かること

- **いつ**：確認できた録音日時。取り込み日時で録音時刻を補いません。日時不明は不明と表示します。
- **何を話したか**：Codexが文字起こしから作る、根拠発言付きの短い要点。発話の先頭を切り取った
  旧`topics.summary`を、生成した要約として表示しません。
- **何が抜き出されたか**：カテゴリ別件数と代表項目。詳細では確認待ち、保存済み、追加済みを
  区別します。確認待ち以外になった項目も、その会話から確認できます。
- **どこか**：録音開始時刻へ照合できたGPSと精度・時刻差。地図から確認でき、未照合の場合は
  日時不明、近い時刻のGPSなし、精度不足などの理由を表示します。
- **何が根拠か**：要点・候補の発話原文、話者ラベル、音声内時刻。推定と確定事項を区別します。

録音の文字起こし中、整理待ち、整理中、失敗、整理済みだが項目なしを別々に表示します。
取得に失敗したときは前回取得した詳細を保持し、通信失敗を「会話がない」と扱いません。
一覧は全録音の原文や発話ごとのGPSを取得せず、詳細を選んだ時に必要な根拠を取得します。

## 抽出する内容

以下は抽出方針の例であり、実際の録音から得られた結果ではありません。

| 種別 | 抽出する内容の例 | 区別すること |
| --- | --- | --- |
| タスク | 「金曜までに見積書を確認する」 | 未完了の具体的な行動。済んだ話や否定された用事を除く |
| フォローアップ | 「返事が来なければ来週確認する」 | 約束・返答待ち・後で確認すること |
| 予定 | 「土曜のイベントに参加したい」 | 検討と参加の意思を区別。予約完了を推測しない |
| 決定 | 「今回はA案で進めることにした」 | 本当に決まったこと。案だけの段階を除く |
| 調べもの | 「二つの製品の違いを調べたい」 | 具体的な質問や比較。公開用の調査文は個人情報を除く |
| アイデア | 「準備をまとめて済ませる方法を試したい」 | 後で検討できる具体的な提案 |
| 困りごと | 「毎回の再入力に時間がかかる」 | 改善対象になる具体的な不便 |
| 関心 | 「今後はデータ品質を勉強したい」 | 本人が明言した継続的関心や目標。単なる話題と区別 |
| 好み | 「静かな店を好む」 | 発言者・明示された対象者の好み。アプリ所有者に自動帰属しない |

会話内容の要約と、生活の管理へ使う候補は別です。用事がない雑談でも、話した内容を要約できます。
逆に、文字起こしが足りない場合に架空の用事や人物情報で欄を埋めません。

## 抽出品質の変更

旧方式では「必要」「お願いします」などの単語を含む発話区間を、そのまま明確なタスクとして
表示していました。これでは否定文や文の途中までが候補になります。新しい補助ルールは、
対象が分かる完結した依頼だけを候補にし、それも確認が必要な候補として扱います。
否定・完了・引用・条件文・指示対象が不明な断片は、文脈を読める整理処理へ任せます。

既存の未確認ルール候補のうち、この基準に合わないものは一覧・候補の応答から除外します。
DB内の状態・原文・根拠は変更しません。本人が編集・保存・採用したものやCodex由来のものは、
この補助ルールで除外しません。件数・代表項目・詳細には同じ判定を使用します。

要約生成のCodexには短い入力専用の発話IDを渡し、返答を保存時のIDへ厳密に戻します。
存在しないIDの要点は受け入れません。要約の根拠を、実際の発話へ結び付けたまま保存します。
長い録音を分割した場合は、その範囲と分割数を保持します。別の区間で話が撤回されたことまで
常に解釈できるとは保証せず、根拠と前後の原文を確認できるようにします。

文字起こしが間違っていれば、根拠付き要約でも内容が間違うことがあります。今回の変更は
録音ごとの表示・整理・断片候補の改善であり、音声認識そのものの正解率向上ではありません。

## 再生成とデータ境界

会話の要約は、候補の抽出とは独立した生成処理と保存領域を使います。自動整理が有効な
新規録音では、候補整理の成功後に要約を作ります。要約だけを作る場合は
`POST /api/conversations/{id}/overview`に空のJSONを送り、候補と採用済み内容を変更しません。
画面から要約を更新する操作もこの経路です。同じ本文・生成版・モデルの完成済み要約は
再利用します。音声を再文字起こしする操作とは別です。

通常の候補抽出・再整理の保存方式は変更しません。要約更新の失敗時は、既存の要約と
採用履歴を保持します。

Codexへ渡すのは既存の整理で許可された録音日時・話者ラベル・発話時刻・文字起こしです。
GPSはMac内で照合し、Codexへ送りません。音声原本・ファイル名・他の録音も送りません。
場所の候補はGPSの推定であり、店名・訪問・同席者の確定に使いません。

`GET /api/conversations`の各録音に軽量な`digest`を付加し、既存の項目を維持します。
`GET /api/conversations/{id}`では要約全体と発話・抽出項目の根拠を確認できます。
要約は`conversation_overviews`に保存し、元入力・生成版・発話IDを保持します。

## 検証

匿名の会話で否定文・断片・根拠ID・空の結果・処理失敗・再生成・保存済み項目の保持・
日時不明・GPS照合を検証します。iPhone/macOSは後方互換デコード、遅いAPIでも一覧が表示されること、
詳細の取得失敗時に表示を保持することを確認し、両OSのビルドと配信検証を行います。
実データの確認時は、録音本文・正確な座標・資格情報をGitや公開ログへ含めません。
