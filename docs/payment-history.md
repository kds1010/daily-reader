# PayPayの支払い明細

「今日」→「PayPayの支払い明細」から、PayPay個人向けの取引履歴CSVを取り込めます。
iPhone・macOSで同じMac miniの明細を表示します。ファイルの取得は手動です。

1. PayPayの「取引履歴」から期間を指定し、ダウンロードを申請します。
2. PayPayの通知を受け取ったら、24時間以内にCSVをダウンロードしてファイルへ保存します。
3. Daymeldで「CSVを選択して取り込む」を押します。追加・重複・競合件数を確認します。
4. 一覧の「期間を指定」で日本時間の開始日・終了日を選び、「表示期間を適用」を押します。
   開始・終了日の両方を含みます。「CSVの詳細」で元の各列を確認できます。

元CSVは変更・削除しません。保存した取引は自動更新されません。画面の「最終取り込み」は
Macへの取り込み日時であり、PayPayとの同期成功を示すものではありません。
同じファイルの再送では元の取り込み日時を維持します。

## 公式根拠と対応形式

2026-09-08に確認した[PayPay個人向け公式ヘルプ](https://paypay.ne.jp/help/c0447/)に、
UTF-8、コンマ区切り、次の13列が記載されています。

| 列 | Daymeldでの扱い |
| --- | --- |
| 取引日 | `YYYY/MM/DD HH:mm` または `YYYY/MM/DD HH:mm:ss` |
| 出金金額（円）、入金金額（円） | カンマ付き／なしの非負整数。空欄・`-`は未記載として保持 |
| 海外出金金額、通貨、変換レート（円）、利用国 | 原文を保持。独自に円換算しない |
| 取引内容、取引先、取引方法 | 原文の種別・取引先・支払い方法を表示。複合支払いを分割しない |
| 支払い区分、利用者 | 詳細に原文を表示 |
| 取引番号 | 文字列。先頭ゼロ・長い番号・`lp-`接頭辞を保持 |

[公式のCSV画像](https://about.paypay.ne.jp/uploads/2025/01/20250206-01-img02.png)で
秒付き日時、桁区切り、欠損の`-`も確認しています。画像は「利用者」までの12列ですが、
初期版は現在のヘルプにある13列を必須にしています。列順の変更は許容し、追加列は
原文として保持します。必須列の改名、重複列名、12列の旧形式、CP932、ZIP、PDF、
負数・小数・通貨記号付きの円金額は未対応として取り込み全体を拒否します。
UTF-8 BOM有無、CRLF/LF、引用符内のカンマ・改行は対応します。

公式CSVにタイムゾーンの宣言は見当たりません。Daymeldは国内個人利用の初期設定として
日本時間（Asia/Tokyo）と解釈します。元の日時文字列は詳細に残し、分までのデータは
保存形式上だけ秒を0にします。海外での表示時刻が異なるCSVは個別確認が必要です。
取得時刻やインポート時刻を取引日時へ代用しません。

[PayPayの公式案内](https://about.paypay.ne.jp/pr/20250206/01/)では直近2年間、1回365日以内を
取得できます。CSVは申請時点の状態で、一部の処理中・失敗・取消などは含まれません。
[ヘルプ](https://paypay.ne.jp/help/c0447/)ではカード利用の取引先が「お店」となる場合も
説明されています。具体的店名や購入商品、完全な残高を取得できるとは限りません。
出金・チャージ・返金・ポイントなどを原文のまま区別し、消費支出合計は算出しません。

[公開開発資料](https://developer.paypay.ne.jp/products/docs)は加盟店向けです。
個人の全店舗の支払い履歴を読み取る公開APIは確認できておらず、ログイン自動化や非公式APIは
使用しません。Gmailの未読管理、他社決済の取り込み、会話・GPSとの連携は含みません。

## 重複と競合

- 同一バイト列のファイルはSHA-256で識別し、再送しても明細を増やしません。
- 取引番号がある行はPayPay内の番号で照合します。日時・円金額の表記だけの違いを正規化し、
  その他の全列を含む内容が同じなら重複とします。別番号の同日時・同額の決済は保持します。
- 同一番号で内容が異なる行は競合として保存せず、既存行を保持します。同じファイル内の
  競合も同様です。競合件数と先頭100件のCSVレコード番号を表示します。ヘッダーを1とし、
  引用符内の改行はレコードを増やしません。競合以外の正常行は保存します。
- 番号の一意性や欠損条件は公式資料で確認できません。競合は自動で訂正せず元CSVとPayPayで
  確認してください。初期版には上書き・訂正操作はありません。
- 番号が空欄または`-`の行はファイルハッシュとレコード番号で保持します。同じファイルの
  再送は重複しませんが、別ファイル間では同じ取引が増える可能性があります。日時・店舗・
  金額だけで誤統合せず、番号なし件数を表示します。期間の重ならないCSVを使ってください。
- UTF-8・列数・日時・円金額などの不正が1行でもあれば、そのファイル全体を保存しません。
  DBへの保存も1トランザクションです。競合による行の保留とは区別します。

## 保存とAPI

`src/daily_reader/payment_history.py`は標準ライブラリだけを使います。
`data/payments.sqlite3`の`payments`と`payment_imports`へ保存します。DBは0600、
DB・ジャーナル類はGit管理外です。取り込んだ各行の原文・ファイルハッシュ・CSVレコード番号を
保持し、CSVファイル自体やファイル名はサーバーへ保存しません。

`POST /api/payments/import`にCSV本文を`text/csv`で送ります。
`Content-Length`を必須にし、10 MiB、50,000行、64列、1フィールド2,048文字を上限とします。
応答は`total`, `added`, `duplicates`, `conflicts`, `missing_ids`, `conflict_rows`,
`imported_at`, `file_duplicate`です。ヘッダーだけのCSVも0件として扱います。

`GET /api/payments?start=YYYY-MM-DD&end=YYYY-MM-DD&limit=100&offset=0`は省略時に全期間、
100件を返します。limitは1〜500、offsetは0〜1,000,000です。日時降順・ID降順に並び、
`items`, `total`, `offset`, `has_more`, `last_imported_at`, `missing_ids`を返します。
各ページ内の件数とデータは同一DBスナップショットです。ページ間で別端末が取り込んだ場合は
一覧を再読み込みしてください。`missing_ids`は全期間の番号なし件数です。

API応答は`Cache-Control: no-store`です。PayPay資格情報は不要です。
既存の8787とtailnet内443だけで使い、SideStoreの8788/8789やFunnelへ明細を公開しません。
支払いAPIだけ、Hostを`127.0.0.1`、`localhost`、`sk-mins-mac-mini.tailc193b2.ts.net`に限定し、
異なるOriginとcross-siteブラウザリクエストを拒否します。既存の接続設定を変える必要はありません。
`--payments-db`は既存DBオプションと同じ形式のサーバー引数で、テスト用のDBを分離できます。
明細・取引先・元ファイル名をURL、アクセスログ、エラー、ニュース生成、Codexへ渡しません。
UIのDebug fixtureではアップロードを無効にし、実APIへ読み取りもしません。

macOSのApp Sandboxには、本人が選択したCSVを読むための
[`com.apple.security.files.user-selected.read-only`](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.files.user-selected.read-only)
を追加しています。書き込み権限は追加せず、配布スクリプトでも読取専用権限の存在を検証します。

## 検証とデプロイ

匿名の`tests/fixtures/paypay.csv`、`tests/test_payment_history.py`、
`tests/test_local_server.py`、`tests/test_payment_native.py`で保存、再送、競合、番号欠損、
不正入力のロールバック、期間・ページング、HTTP、Swiftの実デコードを検証します。
加えてリポジトリ必須チェックとDailyReader/DaymeldMacのXcodeビルドを実行します。

mainへの統合・push後はWeb LaunchAgentの再起動、PID/待受/HTTP/明細API確認、
iPhone・Mac両方の最新配布成果物生成と配信確認が必要です。Agentワーカーの変更はありません。
初回の実明細取り込みとiPhoneへのインストールは利用者が行う独立した工程です。
